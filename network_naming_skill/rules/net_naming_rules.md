# 网络命名规则

分清“命名组”和“分析族”：

```text
命名组：最终只能回填一个网络名
分析族：多个命名组一起分析，用于统一总线前缀、差分主体和编号规律
```

## 分组规则

1. `#` 表示总线展开，不是命名分组后缀。`BUS#1`、`BUS#2` 是不同物理成员、分别生成网络名，但必须一起分析；名称前缀一致，末尾使用不同关键字或数字。
2. `_数字` 是连线 ID 的命名分组后缀。只有连线方向为 `OUTPUT`，且 Block + 实际原理图 pin 相同，才比较下划线后的数字。
3. `OUTPUT` 方向 + 相同 Block + 相同实际 pin + 相同 `_数字` 后缀，四项同时满足时才属于同一个命名组，即使连线 ID 前缀不同；组内网络名必须一致。
4. 相同 `OUTPUT` Block + 实际 pin 下，不同 `_数字` 后缀属于不同命名组，但必须放进同一分析族，让模型看全所有后缀后再命名。
5. `INPUT` 或方向为空不能触发跨连线 ID 的后缀合组。没有 `_数字` 后缀时也不因 pin 相同就跨 ID 合并；同一完整连线 ID 的两端记录仍只命名一次。

示例：同一个 `BLOCK_A/PIN_X` 上存在 `LEFT_1`、`RIGHT_1`、`LEFT_2`、`RIGHT_2`，则形成两个命名组：

```text
组1 = LEFT_1 + RIGHT_1
组2 = LEFT_2 + RIGHT_2
```

两个组一起分析，分别得到一个网络名。

## 命名优先级

1. 先查找命名组内 OUTPUT 记录的非空“连线名称”；若只有一个不同值，逐字作为网络名，优先级最高，不再进行模型分析或格式清洗。OUTPUT 名称全部为空时，才按相同方法查找其他端名称。
2. 同组多个端点重复出现相同连线名称不算冲突；同一优先级出现两个或更多不同的非空连线名称时，必须停止并报告冲突。较低优先级端点的不同名称不能覆盖唯一的 OUTPUT 名称。
3. 只有整组“连线名称”均为空时，才由模型结合全部端点、实际 pin、`analysis_notes` 和本规则分析命名。

以下格式规则只约束模型生成的网络名，不改写直接采用的连线名称。

## 模型任务精简规则

只维护下面两个标记之间的列表，`prepare_naming.py` 会在每次运行时自动读取并嵌入 `naming_groups.jsonl`，不要在脚本中另建规则副本。

<!-- MODEL_TASK_RULES_START -->
- 综合命名组全部端点、实际 pin 和分析说明，不按单行视角命名。
- 优先采用能表达信号功能的 port 或 pin，Block 使用英文简称。
- 输出 SCREAMING_SNAKE_CASE，字母开头且不超过 31 字符。
- 差分保留 P/N；总线成员保持共同前缀并保留各自位号或关键字。
<!-- MODEL_TASK_RULES_END -->

基本格式优先使用：`端点block英文简称_端点block英文简称_信号功能`。命名时必须综合该组的全部端点，不固定采用 Excel 某一行的源端视角。

其中：

```text
1. 源block名和目的block名必须转换为英文简称。
2. 从全部端点 port 和实际 pin 中选择最能表示信号功能的一个标识拼接到末尾。
3. port 选择优先级：
   a. 先看 port 是否有含义；有含义的优先选择。
   b. 如果源/目的 port 都有含义或都没有含义，则优先选择包含数字的 port。
   c. 如果仍无法区分，优先选择能与同一基础连线族其他成员形成一致总线/差分模式的 port。
4. block 和 port 中的中文必须翻译为英文或英文缩写。
5. 最终网络名使用 SCREAMING_SNAKE_CASE。
```

输入 Excel 中已有的旧“网络命名”不能覆盖本次结果。`automatic_decisions.jsonl` 中的连线名称直用结果与 `naming_decisions.jsonl` 中的模型结果共同构成本次回填的权威 decision。

差分信号必须保留 `_P/_N`；`#` 总线展开成员必须保留各自位号或关键字。不能把 `#1/#2` 误当成 `_1/_2` 命名分组后缀。

模型分析时必须读取命名组的 `analysis_notes`，它来自 Excel 原“分析说明”；该内容用于理解 pin 映射依据和信号功能，但不能覆盖非空连线名称的最高优先级。pin 分析 skill 输出的“网络命名”固定为空，本 skill 在保留分析原文的前提下追加或刷新“网络命名依据”。
