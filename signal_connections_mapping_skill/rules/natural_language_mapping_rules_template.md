# 自然语言映射规则入口

本文件描述规则体系的分层结构和优先级。具体规则分散在以下子目录中，由脚本自动收集合并：

- `rules/device_rules/` — 器件级规则，按器件编码组织
- `rules/link_rules/` — 链路级规则，按链路类型组织
- `rules/signal_rules/` — 通用信号规则
- `rules/global_mapping_rules.md` — 通用硬件语义规则
- `rules/link_family_guide.md` — 链路族概念说明

## 规则分层

```text
0. 链路族规则：描述重复链路族、代表链路、链路方向、器件角色、索引和 P/N 传播。
1. 链路级规则：描述一类业务链路的拓扑、索引、器件间连接关系。
2. 器件级规则：描述某个器件 code/料号下，各 pin 或端口的功能。
3. 通用信号规则：描述 SPI、差分、电源、时钟等通用协议/信号族。
```

## 裁决优先级

```text
用户当前明确说明
  > 链路族/链路级语义
  > 当前器件上下游
  > 器件级局部规则
  > 通用信号规则
  > pin 名称相似度
```

## RULE 块格式

规则块用于脚本做轻量召回。格式保持自然语言，标题必须使用：

```text
### RULE: <器件code或名称> <规则ID/简短名称>
```

器件规则的标题必须明确包含适用器件的 code 或名称。标题是硬门控；“适用条件”和正文只能进一步缩小范围，不能让标题未命中的器件规则被召回。最终是否使用通过门控的规则，仍由 subagent 结合框图连接、链路上下文、源端 pin 列表逐条判断。

脚本会根据规则所在目录写入层级元数据，并按以下方式确定性召回：

- `link_rules/`：按 `链路类型` 与当前 `link_family_id` 召回
- `device_rules/`：先按 `### RULE` 标题中的器件 code/名称严格匹配当前源端或目标器件，再核对 `源端器件`/`目标器件` 条件
- `signal_rules/`：按 `映射族`、`典型端口` 或 `signal_shape` 召回
- `global_mapping_rules.md` 与 `SIGNAL_SPECIAL`：作为通用约束常驻

同一个 RULE ID 在外部 project/user rules 中再次定义时，后出现的定义覆盖内置定义。关键词补充召回不适用于器件规则。
